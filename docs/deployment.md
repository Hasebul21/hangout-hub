# Deployment

What runs where:

| Part     | Where                    | URL                                      |
| -------- | ------------------------ | ---------------------------------------- |
| Client   | Vercel, project `hangout-hub` | https://hangout-hub.vercel.app       |
| Backend  | Render, free web service | https://hangout-hub-api.onrender.com     |
| Database | Neon Postgres            | (connection string in Render env)        |

All of it is on free plans.

## Client on Vercel

The Vercel project is connected to the GitHub repo, so every push to `master` deploys.

Project settings:

- Root directory: `hangout-hub-client`
- Build command: `npm run build:vercel` (a production Angular build)
- Output directory: `dist/hangout-hub/browser`

`hangout-hub-client/vercel.json` has a rewrite that sends every path to `index.html`, so refreshing on `/chatroom` still works.

The backend url is baked into the build from `src/environments/environment.prod.ts`. If the backend moves, change it there and push.

## Backend on Render

Render reads `render.yaml` in the repo root. It builds `hangout-hub-backend/Dockerfile` and runs it in the Singapore region, close to the Neon database.

Environment variables:

| Name              | Value                                                          |
| ----------------- | -------------------------------------------------------------- |
| `DATABASE_URL`    | Neon connection string (set by hand in the Render dashboard)   |
| `OWNER_PASSWORD`  | password for the owner account (set by hand)                   |
| `DATABASE_SSL`    | `true`                                                         |
| `DB_SYNCHRONIZE`  | `true`, TypeORM creates and updates tables on start            |
| `JWT_SECRET`      | generated by Render                                            |
| `ALLOWED_ORIGINS` | the Vercel urls, comma separated                               |

Render redeploys on every push to `master`.

The free plan goes to sleep after about 15 minutes without traffic. The first request after that takes 30 to 50 seconds while it wakes up. If the site says "Login failed" right after a long break, wait a bit and try again.

## Database on Neon

Only the backend talks to the database. Tables are created by TypeORM on start because `DB_SYNCHRONIZE` is on. That's fine for a small project like this. If the data ever matters a lot, switch to proper migrations and turn sync off.

The old Spring version of the app left a `users` table in the same database. Nothing uses it anymore and it can be dropped.

## Things I ran into

- **Railway**: the old backend was on Railway, but the free trial ran out and it couldn't deploy anymore. Railway also hosted Elasticsearch, and Redis was on Upstash, which had deleted the database for being inactive. That's a big part of why the app now only needs Postgres.
- **Vercel for the backend**: it builds fine, but a Socket.IO server that holds connections open doesn't fit serverless functions, and the function hung on start. Render runs it as a normal long-running server, which is what it needs.
- **Neon pooler and locks**: a session advisory lock taken through Neon's pooled connection string never gets released, because the pooler shares connections. The seed uses a transaction lock for that reason. See `seed/seed.service.ts`.
- **sharp**: the native image library failed to load on an arm64 host. Pictures are now resized in the browser instead.

## Deploying by hand

Normally pushing to `master` is enough. To deploy again without a new commit:

- Client: open the latest deployment in the Vercel dashboard and click "Redeploy".
- Backend: use "Manual Deploy" on the service page in the Render dashboard.
